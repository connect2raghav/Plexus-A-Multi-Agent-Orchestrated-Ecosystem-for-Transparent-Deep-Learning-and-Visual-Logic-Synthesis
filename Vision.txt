# Detailed Report for Vibe Coding Agent: Plexus Platform

## 1. Executive Summary

**Plexus** is a no-code, AI-assisted model training and learning platform. Its real motive is not only to draw nodes, but to let a learner upload data, understand that data, get explainable AI assistance, build a model visually, train a real model locally, inspect real metrics, improve the graph, and export usable artifacts without writing code. The platform runs **completely locally** (no cloud). Users drag datasets from a sidebar onto an empty canvas, receive AI-generated or deterministic fallback preprocessing suggestions, assemble layers/models by connecting nodes, train models with real-time visualisation **directly on the canvas** (collapsible tiles), and export results. The system uses **static rules** for common errors and **AI agents** (Data, Architect, Debugger) for complex suggestions. Every interactive element on the canvas is **editable** (sliders, toggles, input fields) and training can be paused/resumed with updated parameters. A modern UI with toast notifications for all actions and errors is required.

Core rule: no feature should be a decorative placeholder. If an item appears in the sidebar or canvas as a training, cleaning, suggestion, deployment, or evaluation feature, it must either execute real logic or be clearly marked as not implemented. Hardcoded demo outputs must be replaced with dataset-derived, model-derived, or job-derived results.

## 2. Complete Vision & How Things Should Work

### 2.1 Core User Journey

1. **Start** – Empty canvas. Sidebar contains: Dataset Upload, Dataset Library, Layers, Visualisation Nodes, Output Nodes.
2. **Upload Dataset** – User uploads CSV (or image zip) via sidebar. Profiling runs (background). Dataset appears in **Dataset Library** (draggable). **No node is auto‑placed on canvas**.
3. **Drag Dataset to Canvas** – User drags a dataset from library onto canvas → creates a **Dataset Node** (shows name, rows, columns). **Immediately** the AI Data Agent starts generating a cleaning script in the background (non‑blocking). A spinner appears on the node.
4. **AI Preprocess** – Once ready, the Dataset Node shows a button **“AI Preprocess”**. Clicking it applies the cleaning and creates a **Cleaned Dataset Node** connected to the original. The original remains untouched.
5. **Build Model** – User drags layers (Dense, Dropout, Conv2D, Flatten, etc.) onto canvas and connects them to the Cleaned Dataset Node. **Static validation** (no AI) checks shape compatibility and highlights errors in red.
6. **Configure Training** – User adds a **Training Config Node** (draggable from sidebar) and sets hyperparameters (epochs, batch size) via **editable sliders/inputs** directly on the node. Changes are live – training will respect updated values.
7. **Train** – Click “Train” button in toolbar. System validates graph, starts training worker, opens WebSocket. **Automatically** a **Training Monitor Node** appears on canvas showing live loss/accuracy charts (collapsible, movable).
8. **Real‑time Visualisation** – Charts update via WebSocket. **X‑Ray effect**: wires between layers pulse with gradient strength. Debugger Agent watches metrics; if overfitting or dead neurons detected, a non‑modal **suggestion pop‑up** appears. User can **Apply** suggestion (adds Dropout, changes LR, etc.) and training continues (after optional pause).
9. **Pause/Resume** – User can pause training, edit any node parameters (e.g., increase epochs, change activation), then resume – system restarts training with new config (or continues from checkpoint).
10. **Results** – After training, an **Evaluation Results Node** automatically appears on canvas (confusion matrix, final metrics). User can add additional visualisation nodes (e.g., “Prediction Samples”) manually from sidebar.
11. **Deploy** – Drag **API Node** from sidebar, connect to trained model. Clicking it generates downloadable Docker + FastAPI app.

### 2.2 Key Behaviours & Rules

- **No initial input boxes** – Canvas starts empty. Everything is drag‑and‑drop.
- **Every tile (node) is editable** – Each node has a settings panel (gear icon) or inline controls: sliders for epoch count, learning rate; dropdowns for activation functions; number inputs for layer units. Changes take effect when training is restarted (or after pause/resume).
- **Training respects dynamic changes** – If user changes epochs from 10 to 20 while training is paused, clicking “Resume” uses the new value. If model architecture is changed (layer added/removed), training must restart from scratch (with warning).
- **Notifications** – Top‑left corner shows snackbar/toast for every action: “Dataset uploaded”, “Cleaning script ready”, “Training started”, “Suggestion: Add Dropout”, “Error: Conv2D needs 4D input”. Errors also appear as red tooltips on canvas nodes.
- **Dataset Library & Cleaning** – After upload, the dataset appears in the **same library** as models and layers. The user must drag it to canvas. The “AI Preprocess” button is **only visible after the dataset node is on canvas** and the cleaning script is generated.
- **Separate results panel** – Optional side panel can show summary metrics, but the **primary** visualisation is on canvas nodes (Training Monitor, Evaluation Results). These nodes are collapsible and movable.

## 3. New Requirements (Not yet in previous agent instructions)

### 3.1 Editable Nodes with Live Config Changes

- Every trainable parameter (epochs, batch size, learning rate, layer units, dropout rate) must have an interactive control **on the node** (or via a property sidebar that updates the node in real time).
- When user changes a parameter **while training is not running**, the new value is stored. If training is later started, the new value is used.
- If training is **paused** and a parameter changes, the training loop should detect the change and either:
  - Apply it immediately (if it doesn’t require model re‑initialisation, e.g., epochs), or
  - Show a warning and require restart (e.g., changing number of layers).
- Provide **Pause**, **Resume**, **Stop** buttons on the Training Monitor node.

### 3.2 Modern UI/UX & Notifications

- Use a **glassmorphism/neomorphic** style with smooth animations.
- **Toast notifications** (top‑left, auto‑dismiss after 4 seconds) for:
  - Success: “Dataset ‘iris.csv’ profiled”, “Cleaning script generated”, “Training started”, “Model exported”.
  - Warning: “Cleaning script failed – using fallback”, “Validation loss increased”.
  - Error: “Connection shape invalid”, “GPU out of memory”.
- All errors that appear on canvas must also appear in the notification history (accessible via a small bell icon).

### 3.3 Dataset Visibility & Cleaning Options

- After upload, the dataset must appear in the **same sidebar tab** as layers and models. Not a separate section.
- The dataset node on canvas **must have** a visible “AI Preprocess” button (or context menu option) after the cleaning script is ready. If the script fails, show a “Manual Clean” button that opens a simple form (drop columns, impute, scale).
- Cleaned dataset node should have a distinct colour/badge to indicate it is derived.

### 3.4 Training & Model Actually Happens

- The backend **must actually train** a neural network (PyTorch) using the graph topology provided. No mock training.
- Generate Python code from the graph and execute it in a subprocess (or Celery worker). Stream real metrics.

### 3.5 Additional Missing Features

- **Model Templates** – Pre‑built architectures (ResNet‑18, LSTM) that expand into nodes when dragged.
- **Checkpointing** – Save model weights every N epochs; allow resume from checkpoint.
- **Hyperparameter Search** – Basic grid search slider for epochs and learning rate (optional).

## 4. Architectural Requirements (Repeated for Clarity)

- **Local only** – No cloud. Files stored in `./uploads`. Use local Celery+Redis, SQLite for metadata.
- **FastAPI backend** with WebSocket for real‑time metrics.
- **React + React Flow frontend** (Next.js optional but not required).
- **Static rules engine** for shape validation and common errors (implemented in Python, exposed via API, also run on frontend for immediate feedback).
- **LLM integration** (OpenAI or local via Ollama) for Data Agent (preprocessing) and Debugger (complex suggestions). Use environment variables for API keys.
